# 功能選擇與客製化

首次啟用時，先幫老闆選「想解決的問題」，不要先問會計科目、要對方自己發明功能，或未經確認就替他定案。

## F0 功能範圍關卡

若沒有既有 Company Accounting Pack，或 `feature-selection.json` 尚未是 `OWNER_CONFIRMED`，第一個實質問題必須是功能多選。使用者在 prompt 中寫「幫我建完整系統」或 UI 的 default prompt，只能當作 AI 推薦來源，不能當作負責人已確認。

F0 未確認前不可：

- 自動把主模式定為 `setup`。
- 開始產業或會計準則研究。
- 讀取銀行、客戶、員工、股東、稅務或其他敏感資料。
- 建立 Company Accounting Pack、選定正式帳務來源或寫入任何公司資料。

F0 完成後，AI 再依多選結果提出 `setup / migrate / operate / review` 的建議執行順序。功能可以多選，`mode` 只代表現在處理的階段，不可用單一 mode 覆蓋其他已選結果。

## 首輪必做

1. 用一句話說明：「我會先幫你選功能；可以直接採用建議、一次多選、取消不需要的項目，也可以新增自訂功能。」
2. 根據已知內容預選一組「暫定推薦」。若尚無公司背景，只預選 `O1` 與 `O2`；不要假裝已做個別化分析，也不要一次勾全部功能。
3. 以 checklist 顯示簡短功能名與一句用途：`[x]` 代表 AI 推薦，`[ ]` 代表選配。明說勾選只是 `AI_PROPOSAL`，不是使用者已同意。
4. 在同一輪提供三種低負擔回覆方式：
   - `照建議`：一次採用所有 `[x]` 項目。
   - `加 Oxx、移除 Oxx`：一次多選或取消。
   - `自訂：<我想解決的問題>`：不受目錄限制。
5. 若使用環境有真正的多選介面，可用多選介面呈現；否則使用上述編號回覆。不可改成「請自由描述你想要的功能」這種空白題。

首輪結尾必須說明：「我收到你的選擇前，不會替你定案、讀取敏感資料或建立檔案。」

## 第一層：老闆選想要的結果

首次只顯示這 8 項，不把全部會計子模組一次丟給老闆：

| ID | 老闆看到的功能 | 交付結果 |
|---|---|---|
| `O1` | 看懂我這個產業的錢怎麼跑 | 商業模式、收款、履約、收入、成本與風險的白話地圖 |
| `O2` | 檢查公司現在的帳哪裡有洞 | 現有帳本、資金通路、憑證、流程與風險缺口 |
| `O3` | 建立公司自己的內帳制度 | 內帳政策、科目、憑證規則、角色、核准與版本 |
| `O4` | 把舊帳整理、搬過來 | 保留原檔的欄位映射、公式/差異風險、試轉與調節 |
| `O5` | 把日常記帳、憑證和待收待付管起來 | 收件、查重、分類提案、應收付、預收付與分錄 |
| `O6` | 對帳、月結，看懂成本、現金與獲利 | 銀行/卡片/平台對帳、標準結構權責損益草案、老闆儀表板、成本與現金視圖 |
| `O7` | 準備給記帳士或會計師覆核與交接 | 待回答問題、來源、暫定處理、調整記錄與交接包 |
| `O8` | 做匯入、串接、週期作業或安全匯出 | 自動化範圍、權限、預覽、回復與異常停止條件 |

## 第二層：只展開相關子功能

選定第一層後，再依實際經濟事件展開子功能，不只依產業名稱。子功能包含：交易與憑證收件、正式帳本與科目、銀行/信用卡/平台對帳、收入/應收/預收、發票與稅務事件、電商/POS/訂閱/退款、採購/報支/應付、存貨/成本、專案/工時/毛利、薪資/承攬/扣繳、固定資產/租賃、股東/代墊/關係人、外幣/跨境/多公司，以及月結/現金預測/稅款預留。

只詢問已選結果所需的子功能，並先用已知事實預選。可一次多選、顯示細節、跳過稍後再設，或增加自訂子功能。

### O6 成本、獲利與儀表板子功能

O6 啟用後，讀 `management-reporting.md`，先用 `management-dashboard-config.json` 顯示以下多選。預選只是 `AI_PROPOSAL`；老闆可回覆「照建議」、「加／移除多個 ID」或「自訂：我想看到……」。

| ID | 老闆看到的功能 | 預設 |
|---|---|---|
| `O6-DASH` | 老闆首頁：本期賺賠、可用現金與今天要處理 | 推薦 |
| `O6-PROFIT` | 標準結構權責損益草案＋每 100 元收入最後留下多少 | 推薦 |
| `O6-COST` | 直接成本、營運費用與前五大成本 | 推薦 |
| `O6-TRUST` | 對帳、暫估、缺憑證、未分類與覆核狀態 | 推薦且不得被報表隱藏 |
| `O6-CLOSE` | 月結進度與阻擋事項 | 推薦 |
| `O6-CASH` | 依帳載分類的可動用與受限現金 | 現金科目與總帳完整時選配 |
| `O6-MONEY` | 客戶欠款、平台未撥與公司待付 | v1.3 只記需求草案，擴充驗證後才能 close |
| `O6-DIMENSION` | 產品、專案、門市或通路獲利 | 有可追溯維度與分攤政策時選配 |
| `O6-TREND` | 收入、毛利、營業利益與淨利趨勢 | v1.3 只記需求草案，擴充多期資料契約後才能 close |
| `O6-BUDGET` | 正式預算與實際差異 | 已有可追溯預算時選配 |
| `O6-TAX-RESERVE` | 稅款預留追蹤 | v1.3 只記需求草案；不等於應納稅額 |
| `O6-SCENARIO` | 收款延遲、成本變動等情境 | v1.3 只記需求草案，擴充假設契約後才能 close |

先問老闆這份報表要協助什麼決策、最想拆哪個維度、要比較什麼期間或目標；沒有正式預算時不可把零當預算。子功能確認狀態寫入 dashboard config，不需把 O1–O8 schema 改成無限展開的巢狀結構。老闆仍可新增任意自訂報表需求；若自訂數字尚未定義機器可讀來源、公式、調節與驗證不變量，只能保留為需求草案，不能假裝已通過 close。

## 推薦邏輯

將推薦理由寫成白話，不只打勾：

- 資訊不足：只預選 `O1` 與 `O2`。
- 尚未建立穩定帳務流程：推薦 `O1`、`O2`、`O3` 與 `O7`。
- 已有試算表、會計軟體或歷史帳：推薦 `O2`、`O4`、`O6` 與 `O7`。
- 想處理每日交易：推薦 `O5` 與 `O6`；若沒有已確認的公司包，一併推薦 `O2` 與 `O3`。
- 要交給記帳士或會計師：推薦 `O2`、`O6` 與 `O7`。
- 有多平台、訂閱、大量交易或重複人工搬運：推薦 `O2`、`O5`、`O6`，並詢問是否增加 `O8`。

AI 可以更新推薦，但不得自動更改已確認的啟用狀態。要顯示差異，例如「因為你提到年訂閱，我建議在 O5/O6 增加訂閱、履約與預收子功能」，只請使用者確認有變化的項目。

## 不可取消的安全基線

這些不是選配功能：來源可追溯、未知不猜、查重、正式分錄借貸平衡、寫入前預覽、最小權限與隱私、open items、版本記錄與專業邊界。若使用者要求停用其中一項，說明這會阻止本 Skill 進行正式入帳或關帳；可繼續做不寫入的診斷與草案，但不得偷偷略過控制。

## 自訂功能

使用者新增功能時，不因名稱不夠會計就拒絕。先用一句話重述想解決的問題，再最多問 3 個會影響實作的點：

- 想看到的結果或決策是什麼？
- 資料從哪裡來、多久更新一次？
- 誰使用、誰確認，什麼情況需要專業覆核？

將自訂功能存為 `source: custom`，給予 `CUST-` 開頭的穩定 ID，至少記錄名稱、期望結果、輸入、輸出、驗收條件、頻率、優先順序、相依功能、風險觸發條件與是否需專業覆核。若要求超出本 Skill 的會計系統範圍，可先保留為期望功能，清楚標示 `out_of_scope` 與建議交接方式，不要偽裝已經實作。

## 確認、修改與停用

- 使用者回覆「照建議」或明確的「加/移除 Oxx」時，該回覆就是多選確認，不要再多問一次。若是模糊自由文字，先重述理解後再確認。
- 確認後顯示「已選、未選、自訂、稍後處理、需專業覆核」摘要與 AI 建議的執行順序。
- 確認摘要結尾固定告知：「之後隨時輸入「修改功能」，即可新增、停用、排序或修改自訂功能；我只會顯示差異，收到你確認後才生效。」
- 未確認前，`selection_status` 維持 `DRAFT`；不得寫成 `OWNER_CONFIRMED`。
- 可隨時回到「修改功能」：新增、停用、調整優先順序、修改自訂結果。保留變更摘要，不刪掉歷史。
- 功能停用不代表刪除相關會計事實或原始證據。
- 商業模式訪談完成後再做一次「推薦差異」檢查；月結時只在有新風險或營運變化時建議調整，不每次重問整份清單。

## 儲存

G0 前只在對話中顯示選擇草案。G0 完成後，將完整 `O1`–`O8` 目錄與自訂選擇寫入 `feature-selection.json`，並在 `interview-state.json` 建立對應的 `owner_confirmed_decisions` 記錄。`selection_confirmation.decision_reference` 必須指向該記錄；`revision` 與 state/manifest 的 revision 必須一致。

每個 feature 至少記錄：`feature_id`、`name`、`source`、`lifecycle_status`、`recommendation`、`priority`、`rationale`、推薦來源、`desired_outcome`、`inputs`、`outputs`、`acceptance_criteria`、`frequency`、`dependencies`、`professional_review_required` 與 `risk_triggers`。未確認時只能是 `PROPOSED`；確認後改為 `ENABLED` 或 `DECLINED`。後續停用用 `DISABLED` 並在 `change_history` 留存變更者、時間、前後 revision、影響功能與原因，不刪掉歷史功能。
