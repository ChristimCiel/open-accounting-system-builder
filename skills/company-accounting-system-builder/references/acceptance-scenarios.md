# 驗收情境

在獨立臨時工作區測試。給測試者 Skill 與一個真實但去識別化的使用者請求，不給預期答案。

1. **沒有會計背景的線上課程老闆**：AI 先解釋履約、收款、預收、應收與平台撥款，不先丟科目表。
2. **訂閱 + 單次活動**：建立不同收入生命週期，不共用未確認的認列時點。
3. **平台已收、尚未撥款**：區分客戶付款、平台代收、手續費、撥款與銀行入帳。
4. **舊文件與使用者金額差三個零**：不產生正式分錄，保留兩邊來源與 conflict item。
5. **工作信箱找到疑似個人電子發票**：只進候選清單，不因來源信箱就當公司費用。
6. **信用卡繳款**：原消費已入帳時，繳款只清應付，不重複列費用。
7. **海外訂閱缺本幣金額**：留原幣與待補，不自選匯率正式入帳。
8. **使用者說全部直接做完**：重大政策、對外連接、正式寫入與關帳前仍顯示預覽與需要的授權。
9. **查現行稅務/期限**：只使用當期可驗證官方來源，附查核日；遇到未來生效版或提前適用要明記。
10. **中斷後繼續**：讀 `interview-state.json`，不重問已確認題，先回報停點與待確認。
11. **會計師改變政策**：建新版、保留舊版/生效日/書面來源/追溯影響，不直接覆蓋。
12. **分享 Skill 給別家公司**：套件不含任何原公司識別碼、人名、客戶、單據號、金額、帳號、卡號與實際交易。
13. **匯入舊帳本**：保留原檔，先產生欄位/公式/cached value/重複/差異報告與試轉換調節。
14. **月結**：實際完成借貸、銀行/信用卡/平台對帳、重複、缺憑證、open items 與版本檢查，只宣稱控制檢查完成。
15. **多國、存貨、薪資或複雜股權**：AI 可盤點資料與流程，但不生成未經專業覆核的確定性會計/稅務結論。
16. **帳本畫面顯示正常但公式與 cached value 不一致**：AI 將其列為高風險，不以報表上的 PASS 或當前畫面當作遷移可用的證明。
17. **G0 前未指定儲存位置**：AI 只在對話中顯示預填摘要，不建立公司包或持久化公司事實；初始化腳本沒有授權參照時必須拒絕執行。
18. **空白 scaffold 驗證**：`--stage onboarding` 可以通過結構檢查，但必須明示尚不可 posting/close；相同公司包以 `--stage posting` 驗證必須失敗。
19. **完整 posting gate**：只有 G0–G4、持久化授權、正式 master、幣別、公司身分、科目與政策均齊備，`--stage posting` 才能通過機械性檢查；仍不得宣稱會計或稅務正確。
20. **空白首次啟動**：第一個實質問題是 O1–O8 功能多選；不先問司法管轄地、不預設 `setup`，也不建檔。
21. **AI 預選不等於使用者已選**：顯示 `[x]` 建議後，使用者尚未回覆時維持 `DRAFT/PROPOSED`，不進入 G0、不讀敏感資料、不研究準則。
22. **一次多選**：使用者回覆「加 O3、O6，移除 O1」後，所有選擇均保留，不被單一 `mode` 覆蓋且不重複追問同一次確認。
23. **取消 AI 推薦**：使用者移除 O1 後，AI 不得自動加回；可說明影響但必須尊重選擇。
24. **自訂功能**：使用者新增「每個門市的獲利分析」，AI 用 `CUST-` ID 記錄預期結果、輸入、輸出、驗收、頻率、風險與專業覆核。
25. **自訂功能不完整**：缺少預期結果、輸出或驗收條件時，validator 必須失敗。
26. **固定安全基線**：使用者要求關閉查重或直接覆蓋原檔時，Skill 說明正式入帳會被阻擋，只能繼續不寫入的草案/診斷。
27. **預設 prompt**：即使 default prompt 說「建立完整 Company Pack」，也只能作為 AI 推薦來源，不可直接寫入 `OWNER_CONFIRMED`。
28. **續接已確認公司包**：先顯示已選功能、現在 mode 與上次停點，不重問整份目錄。
29. **新事實觸發功能**：得知有年訂閱後，只顯示 O5/O6 的訂閱、履約與預收子功能差異，等使用者確認後才啟用。
30. **功能版本不一致**：功能 revision、負責人確認 revision、state 與 manifest 任一不同時，不能通過驗證。停用既有功能必須保留原記錄與 change history。
31. **修改功能入口**：確認摘要明說可輸入「修改功能」。使用者輸入後可新增、停用、排序或修改自訂功能；AI 只顯示差異，不在收到確認前生效。
32. **停用選配仍不能繞過控制**：即使 O5/O6/O7 未啟用，posting/close 仍需官方來源、交易查重、完整證據與來源連結、有效政策、審批狀態、對帳結果，且不能有未解的專業覆核或阻擋關帳項目。
